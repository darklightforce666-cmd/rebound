# Token charts

Discover, Analytics and every `#token/MINT` page use TradingView Lightweight Charts 5.2.1. The configured REBOUND mint comes from `src/mainnet-config.js`; launched tokens already link to their own mint page. The generic Coinbase SOL/USD widget and embedded DEX Screener chart have been removed. DEX Screener market statistics remain separately attributed.

The bundled official library renders candlesticks, USD volume, zoom/pan, fit-to-data, six intervals (1m, 5m, 15m, 1h, 4h, 1d), and USD/SOL price selection in the existing theme. This is TradingView's open-source rendering library, not the separately licensed Advanced Charts drawing/indicator suite and not a promise of a tradingview.com listing. TradingView's attribution, NOTICE and Apache license ship with the site.

`GET /.netlify/functions/charts?mint=MINT&interval=15m&currency=usd` discovers a SOL-paired market through GeckoTerminal, then requests up to 500 real OHLCV bars for that exact base mint. Pool network, address, token orientation, quote asset, candle timestamps and OHLC bounds are checked. Among returned eligible markets it prefers Pump venues, then 24-hour volume and liquidity. This preference is a display selection rule, not proof that a pool qualifies for rewards. Its pool address/source link is displayed. A changed market resets the series; different pools are never spliced into invented continuous history.

Price is USD or SOL according to the selected control; provider volume remains USD. This API feeds only the chart. It does not feed loss calculations, recognize purchases, authorize rewards, or replace the independent finalized indexer and price verifier.

New mints appear once the provider indexes their market and trades. An unindexed mint, unsupported quote, missing history, upstream outage or rate limit displays its actual state. No generated candles or SOL/USD substitute are provided. Gaps remain gaps; no-trade bars are not synthesized. Last trade-candle and fetch times are displayed. Updates run about once per minute, pause across navigation, and preserve zoom on the same series. Failed refreshes label retained data as delayed.

The public provider requires no API key. Netlify's `charts` function must be deployed for the route to work; GitHub Pages cannot run it. The service uses bounded responses, fixed upstream URLs, a bounded process cache, concurrent-request deduplication, 30-second candle caching and 60-second market caching. Netlify response caching reduces repeat requests. The public upstream's documented 30 requests/minute limit and per-instance local budgets are not a global production quota guarantee. Before heavy traffic, provision shared caching and a data plan or independently verified internal chart feed. Never weaken reward-history checks to accommodate chart traffic. During graduation a newly selected market starts with that market's available history; continuity requires a future verified history adapter.

Validation: `node --test tests/charts.test.cjs` covers mint/quote substitution, malformed prices/timestamps, duplicate bars, no-data states, unit selection, request deduplication, cache, request validation, oversized responses and safe provider failure. These are deterministic provider-response fixtures. Live API checks and browser acceptance are recorded in the development handoff, separately from fixture tests.

Sources: [TradingView installation and attribution](https://tradingview.github.io/lightweight-charts/docs), [official library source](https://github.com/tradingview/lightweight-charts), [GeckoTerminal API](https://apiguide.geckoterminal.com/faq).
